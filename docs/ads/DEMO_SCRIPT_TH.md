# บทสาธิต SENA Digital Hub — HYABC / FLEXI

ใช้เวลา 18–20 นาที · ชุดข้อมูลสาธิตเดือนตุลาคม 2569 (`2026-10-01`) · เวลาประเทศไทย

บทนี้ใช้ระบบทดสอบในเครื่องและใบสรุปผลจาก `dev:demo` เท่านั้น ชื่อโครงการและรหัสต้นทางเดิมอาจเป็นข้อมูลจริง แต่ข้อความ สื่อ แบบบ้าน โปรโมชัน งบ และผลการตลาดที่เติมเพื่อสาธิตมีป้ายข้อมูลตัวอย่างกำกับ ไม่ใช่ข้อเสนอขาย งบใช้งานจริง หรือผลอนุมัติจากฝ่ายกฎหมาย/E-memo

## เตรียมก่อนเริ่ม

1. เปิดฐานข้อมูล API และหน้าเว็บตาม [คู่มือพัฒนาในเครื่อง](../11-local-development.md) แล้วรันคำสั่งเดียวจากรากโครงการ:

   ```powershell
   npm.cmd run dev:demo
   ```

2. อ่าน `.local/hub-demo/receipt.json` ซึ่งเป็นไฟล์ในเครื่องที่ไม่ส่งขึ้น Git ตรวจ `status` เป็น `READY`, `environment` เป็น `local-test` และ `presentation_month` เป็น `2026-10-01` หากเป็น `PARTIAL` ให้แก้ขั้นตอนที่รายงานแล้วรันคำสั่งเดิมต่อ อย่าอ้างว่างานเอกสารสำเร็จเพียงเพราะข้อมูลธุรกิจถูกบันทึกแล้ว หากรายงานความขัดแย้ง ให้เก็บข้อมูลที่ผู้ใช้แก้ไว้และตรวจสาเหตุ ห้ามลบข้อมูลเพื่อให้สคริปต์ผ่าน
3. เตรียมลิงก์จากใบสรุปผล ไม่คัดลอก UUID จากการสาธิตรอบอื่น:

   ```powershell
   $demo = Get-Content -LiteralPath .local/hub-demo/receipt.json -Raw | ConvertFrom-Json
   $demo.links | Format-List
   $demo.finance.codes | Format-List
   ```

   ลิงก์ใน `links` คือ `project`, `brand`, `promotion`, `memo`, `card_batch`, `commitment`, `actuals`, `exceptions`, `memo_document` และ `statement_document` พร้อมลิงก์เจาะจง `group_line`/`brand_line`, `group_actuals`/`brand_actuals` และ `group_campaign`/`brand_campaign` เปิดลิงก์ที่แสดงโดยใช้ต้นทาง `http://127.0.0.1:3000` ถ้าลิงก์เป็นเส้นทางที่ขึ้นต้นด้วย `/`
4. เปิดแท็บโครงการ แบรนด์ และโปรโมชันจากใบสรุปผล พร้อมแท็บ [ชุดเผยแพร่ข้อมูล](http://127.0.0.1:3000/releases), [ผลใช้จ่ายเดือนตุลาคม](http://127.0.0.1:3000/ads/actuals?month=2026-10-01), [ติดตามเอกสารเดือนตุลาคม](http://127.0.0.1:3000/ads/documents?month=2026-10-01), [รายการที่ต้องตรวจสอบเดือนตุลาคม](http://127.0.0.1:3000/ads/exceptions?month=2026-10-01) และ [คำถามที่รอคำตอบ](http://127.0.0.1:3000/questions)
5. ตรวจเอกสารก่อนนำเสนอ: Memo V1 ที่ไม่มีการแก้ไขควรมี `memo_review.status = SEARCH_READY` พร้อมหลักฐานตรวจชุดตัวอย่างโดยระบบ นี่ไม่ใช่การตรวจโดยบุคคลจริงหรือการอนุมัติ E-memo ส่วนใบแจ้งยอดควรเป็นร่างสำหรับตรวจต่อ หากเคยตรวจหรือแก้แล้ว ระบบจะรักษาประวัติเดิม ไม่รีเซ็ตให้เป็นร่างเพื่อการแสดง
6. ปิดแท็บที่มีข้อมูลจริงซึ่งไม่เกี่ยวข้อง ไม่ต้องมีรหัสผ่านหรือ API key ในสไลด์ เปิดบัญชีผ่านตัวเลือก **เลือกบัญชีทดสอบ** บนหน้าโครงการหรือทะเบียนแคมเปญ บัญชีนี้ใช้ได้เฉพาะเครื่องพัฒนา

| ช่วงสาธิต | บัญชีที่ใช้ | สิ่งที่ต้องเห็น |
|---|---|---|
| โครงการ แบรนด์ แบบบ้าน และร่างโปรโมชัน | ผู้ดูแลระบบ หรือผู้แก้ไขข้อมูล | ช่องข้อมูลตัวอย่างและความพร้อมเผยแพร่ |
| ตรวจโปรโมชัน เผยแพร่/คืนค่าทั้งชุด | ผู้เผยแพร่ | ปุ่มเผยแพร่ที่ผู้แก้ไขไม่มีสิทธิ์ใช้ |
| ทะเบียน งบ ผลการตลาด และคลังเอกสาร | ทีมออนไลน์ หรือผู้ดูแลระบบ | รายการตามสิทธิ์และป้ายรอคำตอบ |
| ขอบเขตเอเจนซี | เอเจนซี KIN หรือเอเจนซี COMBAY | เฉพาะชื่อของตนและช่องคืน ID; ไม่มีงบ/Memo/ผู้ช่วย |
| ผู้ช่วยและคำถาม | บัญชีพนักงานทั้งห้าบทบาท | เครื่องมือและข้อมูลตามสิทธิ์ของแต่ละบัญชี |

บัญชีผู้ดูแลระบบไม่ได้แทนบทบาทผู้เผยแพร่ทุกขั้นตอน ให้เปลี่ยนเป็น **ผู้เผยแพร่** เมื่อสาธิตการเผยแพร่ แล้วเปลี่ยนกลับก่อนเข้าข้อมูลการเงิน

## 0:00–1:00 — อธิบายขอบเขตและเมนู

**พูด:** “วันนี้เป็นการสาธิตในเครื่องด้วยข้อมูลตัวอย่างเดือนตุลาคม ชื่อโครงการเดิมยังอยู่ ข้อมูลที่เติมมีป้ายกำกับ คำถามธุรกิจยังเปิดอยู่ แต่เราสามารถตรวจการทำงานตั้งแต่ข้อมูลโครงการจนถึงผลการตลาดได้แล้ว”

กดเปิด/ปิดกลุ่ม **ข้อมูลโครงการและแบรนด์** และ **งานโฆษณาและงบ** ชี้ว่าเมนูจำการเปิดแต่ละกลุ่ม และเปิดกลุ่มของหน้าที่กำลังใช้งาน หากใช้จอเล็ก เมนูเรียงแนวตั้ง กด Tab และ Enter ได้

**คำถาม/ผู้รับผิดชอบ:** Q45 — เจ้าของผลิตภัณฑ์การตลาดและผู้รับผิดชอบข้อมูลสาธิต; Q39 — เจ้าของผลิตภัณฑ์และทีมสิทธิ์ผู้ใช้ ค่าเริ่มต้นคือข้อมูลสังเคราะห์ในเครื่องและคำถามทั่วไปสำหรับพนักงาน ไม่เปิดใช้จริงหรือเปลี่ยนสิทธิ์ตามการสาธิต

## 1:00–4:00 — โครงการ HYABC แบรนด์ FLEXI และแบบบ้าน

เปิด `links.project` และ `links.brand` จากใบสรุปผล ชี้รหัสโครงการต้นทาง `HYABC` และแบรนด์ `FLEXI` ให้เห็นความต่างระหว่างข้อมูลต้นทางกับป้าย **ข้อมูลตัวอย่าง** เปิดรายละเอียดป้ายเพื่อดูว่าช่องใดถูกเติม

เปิดแบบบ้านและสื่อที่เตรียมไว้ ชี้ว่าสื่อ/แบบบ้านสังเคราะห์ใช้สำหรับชุดเผยแพร่ตัวอย่างเท่านั้น รายการเดิมที่ยังรอการตรวจไม่ได้รับอนุมัติจากการเติมข้อมูลนี้ หากสคริปต์พบข้อมูลที่ผู้ใช้แก้ไว้แล้ว จะรักษาค่านั้นไว้ ไม่เขียนทับเพื่อให้หน้าดูครบ

**พูด:** “เราใช้รหัสโครงการเดิมเชื่อมงาน แต่ข้อความที่ยังไม่มีหลักฐานมีป้ายชัดเจน ความพร้อมของหน้าโครงการไม่เท่ากับการอนุมัติเผยแพร่”

**คำถาม/ผู้รับผิดชอบ:** Q40 — เจ้าของเนื้อหาการตลาด ฝ่ายกฎหมาย และผู้ดูแลโครงการ ต้องตรวจแทนข้อมูลตัวอย่างก่อนใช้จริง ค่าเริ่มต้นคือเติมเฉพาะช่องที่ขาดและแสดงที่มาของแต่ละช่อง; Q45 — ความสัมพันธ์ขอบเขตกับโครงการที่เตรียมเพื่อสาธิตเป็นของชุดทดสอบ ไม่ใช่การรับรองข้อมูลกลุ่มโครงการจาก DW

## 4:00–7:00 — โปรโมชันและชุดเผยแพร่

เปิด `links.promotion` ตรวจ **ช่วงเวลาไทย** ซึ่งวันสิ้นสุดเป็นขอบเขตที่ไม่รวมเวลานั้น และตรวจชื่อ รายละเอียด เงื่อนไข ข้อกฎหมาย และข้อความสงวนสิทธิ์ เปลี่ยนบัญชีเป็น **ผู้เผยแพร่** ผ่านหน้าโครงการแล้วกลับมาที่ลิงก์เดิม

ใน **การตรวจและเผยแพร่โดยผู้เผยแพร่** ชี้หัวข้อ **ข้อมูล** และ **ข้อกฎหมาย** กับหลักฐานของรุ่นปัจจุบัน ชุดเริ่มต้นมีหลักฐานตรวจตัวอย่าง ไม่ใช่การอนุมัติจากฝ่ายกฎหมายจริง ถ้าแก้ข้อความสำคัญ ผลตรวจเดิมไม่แทนผลตรวจของรุ่นใหม่ อย่ากดตรวจผ่านเพียงเพื่อให้ปุ่มเผยแพร่เปิด

เปิด **ชุดเผยแพร่ข้อมูล** เลือก **ชุดเผยแพร่ข้อมูลตัวอย่าง** เลือกแบรนด์ FLEXI โครงการ HYABC และโปรโมชันตามรหัสในใบสรุปผล โครงการรวมแบบบ้านของตนอยู่ในชุดแล้ว ชี้จำนวนสื่อและแบบบ้านเดิมที่ไม่รวมในชุด ก่อนเผยแพร่ครั้งแรกอาจเห็นคำเตือนว่าฉบับแม่ยังไม่เผยแพร่ เมื่อเลือกแม่กับลูกครบ ระบบจะตรวจลำดับในธุรกรรมเดียว

สำหรับการสาธิตที่ตั้งใจเปลี่ยนสถานะใน TEST ให้กรอก **เหตุผลการเผยแพร่ชุดนี้** เป็น “สาธิตชุดข้อมูลตัวอย่าง HYABC / FLEXI” เลือก **ยืนยันเผยแพร่ทุกรายการที่เลือกเป็นชุดเดียวในระบบทดสอบ** แล้วกด **เผยแพร่ทั้งชุด** ถ้าเพียงนำเสนอแบบอ่านอย่างเดียว ให้หยุดที่ **ทบทวนชุดที่เลือก** และเปิดประวัติที่มีอยู่

**ผลที่คาด:** มีประวัติชุดพร้อมรุ่นที่เลือก ถ้าหนึ่งรายการไม่ผ่าน ต้องไม่เปลี่ยนรายการอื่น หากร่างเปลี่ยนระหว่างเลือก ให้กด **โหลดร่างและฉบับปัจจุบันใหม่** แล้วตรวจใหม่ ไม่ข้ามข้อขัดแย้ง สถานะมีฉบับเผยแพร่แต่ไม่แสดงขณะนี้อาจเกิดจากช่วงเวลา/เงื่อนไขอ่าน จึงไม่ใช่หลักฐานว่าหายไปจากประวัติ

ทางเลือกเมื่อมีเวลา: เปิดประวัติชุด กรอก **เหตุผลการคืนค่าทั้งชุด** เลือก **ยืนยันคืนค่าทุกรายการของชุดนี้** แล้วกด **คืนค่าทั้งชุดเผยแพร่** ใช้เฉพาะเมื่อยอมรับว่าการสาธิตจะคืนค่าทั้งชุด หากมีรุ่นใหม่กว่า ระบบต้องหยุด ไม่คืนค่าเพียงบางรายการ

**คำถาม/ผู้รับผิดชอบ:** Q40 — เจ้าของเนื้อหา/ฝ่ายกฎหมาย; Q41 — เจ้าของงานเผยแพร่และผู้ดูแลระบบ ค่าเริ่มต้นคือผลตรวจตามรุ่น ชุดที่เผยแพร่พร้อมกัน และคืนค่าทั้งชุดเมื่อสถานะยังตรงกัน การเตรียมเดโมไม่เผยแพร่อัตโนมัติ

## 7:00–9:00 — ทะเบียนแคมเปญและขอบเขตเอเจนซี

เปลี่ยนเป็น **ทีมออนไลน์** เปิด [ทะเบียนแคมเปญ](http://127.0.0.1:3000/ads/registry) เปิด `links.group_campaign` และ `links.brand_campaign` หรือค้นหารหัสจาก `finance.codes.group` และ `finance.codes.brand` ในใบสรุปผล

ชี้แถบ **รออนุมัติรูปแบบชื่อ** และ Q2 เปิดรายละเอียดสมาชิกขอบเขต แล้วเปิดแท็บ **ชื่อและลิงก์ติดตาม** กด **คัดลอกชุดข้อมูลสำหรับเปิดแคมเปญ** เพื่อแสดงชื่อที่ตรึงไว้พร้อม UTM ชื่อถูกสร้างโดยเซิร์ฟเวอร์ ไม่มี Memo, BUD หรือยอดงบอยู่ในชื่อ รหัส SN เดียวเชื่อมรายการงบตามเดือนผ่านทะเบียน

ถ้ามีเวลา เปลี่ยนบัญชีเป็นเอเจนซีของรหัสนั้น แสดงว่าเห็นเฉพาะชื่อของตนและคืนรหัสแพลตฟอร์ม/บัญชี/แคมเปญได้ ไม่เห็นงบหรือ Memo และไม่มีผู้ช่วย ไม่แก้ native ID ที่ผูกไว้แล้วเพียงเพื่อสาธิต เปลี่ยนกลับเป็น **ทีมออนไลน์**

**คำถาม/ผู้รับผิดชอบ:** Q2 — พี่โน้ต/เจ้าของรูปแบบชื่อ ค่าเริ่มต้นคือพัฒนาต่อและนำเสนอได้ แต่ `sena_h_approved=false` และการออกชื่อใช้งานจริงยังถูกบล็อก; Q8 — ผู้รับผิดชอบติดตาม Google Ads ต้องยืนยันการรับ `{campaignid}` ก่อนใช้จริง ชื่อที่ออกแล้วไม่ถูกเปลี่ยนโดยการนำเสนอ

## หากสถานะไม่เหมือนรอบแรก

- ใช้ `receipt.json` ล่าสุดและลิงก์ที่ตรึงเดือนตุลาคม อย่าเลือกแถวแรกของชุดทดสอบทุกเดือนมาแทน
- ข้อมูลถูกแก้/มีรุ่นใหม่: แสดงประวัติและโหลดรุ่นล่าสุดตามสิทธิ์ ไม่รันคำสั่งล้างข้อมูล สคริปต์ต้องหยุดเมื่อการเขียนทับจะทำลายงานเดิม
- ผลใช้จ่ายแจ้งว่า Hub เปลี่ยนหลังรอบข้อมูล: อธิบายว่าตัวเลขยังเป็นรอบเดิม ไม่อ้างว่าเทียบกับงบแก้ล่าสุดแล้ว และไม่สร้างการจับคู่ใหม่ในหน้าเว็บ
- เอกสารยังเข้าคิว/ล้มเหลว: รายงานขั้นตอนจริง ใช้คำสั่ง worker ที่คู่มือระบุและรันเดโมต่อได้แบบเก็บสถานะ ไม่เรียกผลการเตรียมทั้งหมดว่าเสร็จ
- โปรโมชันพ้นช่วงเวลา: แสดงฉบับที่เคยเผยแพร่กับเหตุผลที่ไม่เข้าเงื่อนไขปัจจุบัน ไม่ปรับนาฬิกาหรือยืดช่วงเพื่อให้ดูเปิดใช้
- ไม่มีข้อมูล/ไม่มีสิทธิ์/ไม่มี key: ใช้ข้อความสถานะที่หน้าจอแสดง ไม่ปลอมคำตอบหรือยกสิทธิ์ให้บัญชีเพื่อให้เดโมผ่าน
