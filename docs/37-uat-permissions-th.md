# UAT เมนูและสิทธิ์รายบัญชี — รอบเดียวประมาณ 45 นาที

แพ็กทดสอบในเครื่องสำหรับเจ้าของงาน ตามข้อตกลง 9 ตุลาคม 2026 ใช้บัญชีสังเคราะห์และฐานข้อมูล Hub local เท่านั้น ผลรันอัตโนมัติ เลข commit และหลักฐานสำรอง/ตรวจ BNA7 อยู่ใน [บันทึกการส่งงาน](35-permissions-implementation-log.md) ขอบเขตสิทธิ์ที่ตกลงอยู่ใน [แผนสิทธิ์ §10](34-permission-map.md) และกติกาเพิ่มฟีเจอร์อยู่ใน [คู่มือนักพัฒนา](36-adding-feature-permissions.md)

## เตรียมก่อนเริ่ม

- เปิด `http://127.0.0.1:3000/` หลังผู้พัฒนาคืนบริการ local แล้ว ใช้ **เลือกบัญชีทดสอบ** หรือการ์ดบัญชีในหน้าแรก ไม่ต้องกรอกรหัสผ่าน ไม่ใช้ Google/อีเมลจริง และไม่เปิด hosted
- เปิดสองโปรไฟล์เบราว์เซอร์แยกกัน หรือหน้าต่างปกติหนึ่งชุดกับ InPrivate หนึ่งชุด: **หน้าต่าง ก = ผู้ดูแลสำรอง (UAT)**, **หน้าต่าง ข = สมชาย ทดสอบ** แท็บปกติในโปรไฟล์เดียวกันใช้คุกกี้ร่วมกัน จึงไม่เหมาะสำหรับจำลองสองคนพร้อมกัน
- เปลี่ยนสิทธิ์/สถานะเฉพาะสามบัญชี UAT ด้านล่าง ไม่เปลี่ยนแปดบัญชีเดิม ไม่แก้ไข/เผยแพร่ข้อมูลโครงการจริง รวมถึง BNA7 ไม่เขียนไป REM, DW, INVOICE Ads, E-memo หรือ media sheets
- ตรวจสิทธิ์จากเมนู ปุ่ม หน้ารายการ และ HTTP ที่อ่านอย่างเดียวได้ หากต้องเปิดตัวอย่างธุรกิจ ให้ใช้รายการที่ระบุชัดว่าเป็นข้อมูลสังเคราะห์ ไม่ต้องบันทึกเนื้อหาหรือยืนยันรายการการเงินจริงเพื่อพิสูจน์ว่าปุ่มมีสิทธิ์
- ผู้ช่วยใช้เฉพาะ **จำลองในเครื่อง** ไม่เลือกโหมดเรียกผู้ให้บริการ ไม่ใส่ข้อมูลบัญชี คำขอ หรือสิทธิ์ลงคำถามผู้ช่วย ไม่คัดลอกคุกกี้/token/secret ลงบันทึกหรือภาพหน้าจอ

ตัวเลือกบัญชีเป็นเพียงการเลือกตัวตนสังเคราะห์ สิทธิ์จริงต้องอ่านจากบัญชี ACTIVE และตารางสิทธิ์ใน Hub ทุกคำขอ ชื่อตัวเลือกหรือชื่อแม่แบบไม่ใช่ตัวให้สิทธิ์

| ตัวเลือกในเครื่อง | ใช้ตรวจอะไร |
|---|---|
| ผู้แก้ไขข้อมูล | แม่แบบ editor: แก้ไขเนื้อหา แต่ไม่อนุมัติเนื้อหา |
| Manager · อนุมัติและเผยแพร่ | แม่แบบ publisher: อนุมัติเนื้อหา แต่ไม่แก้ไขร่างโครงการ |
| ผู้อ่านข้อมูล | แม่แบบ viewer: ดูเนื้อหาและคำถาม |
| ผู้ดูแลระบบ | บัญชีเดิม: แม่แบบข้อมูล admin และสิทธิ์จัดการผู้ใช้ |
| ทีมออนไลน์ | registry/finance/actuals/documents/archive/exceptions และคำถาม |
| เอเจนซี KIN / เอเจนซี COMBAY | โปรไฟล์ภายนอกตายตัว เห็นทะเบียนของเอเจนซีตนเอง |
| **ผู้ดูแลสำรอง (UAT)** — `uat-admin@example.test` | ผู้ดำเนินการทดสอบ เปลี่ยนสิทธิ์บัญชี UAT อื่น |
| **บัญชีระงับ (UAT)** — `uat-suspended@example.test` | หน้าแสดงสถานะระงับ และการสลับออกจากหน้านี้ |
| **สมชาย ทดสอบ** — `uat-somchai@example.test` | editor รุ่น 1 ที่ปรับเอง: Projects VE, Brands V, Promotions V, Finance VE เท่านั้น |

service_consumer เป็นตัวตนระบบและไม่มีในตัวเลือกเบราว์เซอร์ ไม่ใช้แทนผู้ทดสอบ

## 1. เริ่มงานและเทียบแม่แบบ — 3 นาที

ในหน้าต่าง ก เลือก **ผู้ดูแลสำรอง (UAT)** แล้วเปิด **ผู้ใช้และสิทธิ์ → ผู้ใช้ทั้งหมด** ค้นหา `uat-` ต้องพบสามบัญชี UAT โดยบัญชีระงับมีสถานะระงับ อีกสองบัญชีใช้งานอยู่ ค้นหา **สมชาย ทดสอบ** ต้องแสดงแม่แบบที่ปรับเองและชิปสิทธิ์สี่แท็บตามตารางด้านบน

สลับดูบัญชีเดิมอย่างรวดเร็วโดยไม่แก้สิทธิ์: ผู้อ่านไม่เห็นปุ่มแก้ไข; ผู้แก้ไขไม่เห็นปุ่มอนุมัติ; Manager ไม่เห็นปุ่มแก้ไขร่างโครงการ; ทีมออนไลน์มีแท็บงานโฆษณาและงบ กลับมาที่ผู้ดูแลสำรองก่อนขั้นต่อไป

**คาดหวัง:** เลือกบุคคลแล้วระบบพาไปหน้าที่บุคคลนั้นมีสิทธิ์ ชื่อแม่แบบเป็นจุดเริ่มต้นของกล่องสิทธิ์ ไม่ทำให้มีสิทธิ์เหนือกล่องที่บันทึกจริง

## 2. เมนู 1280 / 1024 / 400 px และแป้นพิมพ์ — 4 นาที

ใช้ responsive mode ของเบราว์เซอร์ หรือปรับความกว้างหน้าต่างตามลำดับ:

| ความกว้าง | ทำอะไร | ผลที่ต้องเห็น |
|---|---|---|
| 1280 px | กด **ย่อเมนู**, รีเฟรช, กด **ขยายเมนู** | เมนูย่อเป็นราง 64 px มี `S.` และจำค่าที่เลือกหลังรีเฟรช |
| 1280 px | ใช้ Tab ไปที่ไอคอน แล้วหยุดโฟกัส | มีชื่อ tooltip ทั้งเมื่อโฟกัสและชี้เมาส์; ถ้ามีคำขอรออนุมัติ badge ต้องยังอยู่บนไอคอน |
| 1280 px | ย่อกลุ่มที่มีหน้าปัจจุบัน แล้วเปลี่ยนหน้า/รีเฟรช | กลุ่มย่อได้จริง มีเครื่องหมายว่าหน้าปัจจุบันอยู่ในกลุ่ม และจำสถานะกลุ่ม |
| 1024 px | เปิดเมนูจากราง แล้วกด Esc; เปิดอีกครั้งและคลิกด้านนอก | เมนูทับเนื้อหา ไม่ดันเนื้อหา; ปิดแล้วคืนโฟกัสไปปุ่มเปิด; โหลดหน้าใหม่กลับเป็นราง |
| 400 px | เปิด drawer, ใช้ Tab/Shift+Tab, กด Esc | โฟกัสไม่หลุดไปหน้าเบื้องหลัง; Esc ปิดและคืนโฟกัส; เมนูเริ่มปิด |

ทุกขนาดต้องไม่มีการเลื่อนแนวนอนทั้งหน้า ตารางผู้ใช้อาจเลื่อนภายในกรอบของตารางได้ ไม่มี transition/animation ใหม่ และปุ่มผู้ช่วยใช้งานได้ทั้งเมนูเต็มกับราง ไม่นับ badge เป็นข้อผิดพลาดหากฐาน local ไม่มีคำขอที่ส่งแล้ว; ภาพและ UI test ที่ระบุท้ายเอกสารมีคำขอสังเคราะห์สำหรับกรณีนี้

## 3. สมชายมีเพียงสี่แท็บ — 3 นาที

ในหน้าต่าง ข เลือก **สมชาย ทดสอบ** ตรวจเมนูและหน้าโดยยังไม่แก้ข้อมูล:

| แท็บ | สิทธิ์เริ่มต้น | ผลที่ต้องเห็น |
|---|---|---|
| โครงการที่อยู่อาศัย | ดู + แก้ไข | ดูรายการ/รายละเอียดที่อนุญาตและมีทางแก้ไขร่าง ไม่มีทางเผยแพร่ |
| แบรนด์ที่อยู่อาศัย | ดู | อ่านได้ ไม่มีทางแก้ไขหรือจัดการรายการแบรนด์ |
| โปรโมชั่นโครงการ | ดู | อ่านได้ ไม่มีทางแก้ไข/อนุมัติ |
| งบและค่าใช้จ่าย | ดู + แก้ไข | ใช้งานร่างได้ ไม่มีปุ่มยืนยันที่ต้องใช้อนุมัติ |
| ทุกแท็บอื่น | ไม่มี | ไม่อยู่ในเมนู รวมถึงคำถาม ทะเบียน คลังเอกสาร และผู้ใช้และสิทธิ์ |

ในหน้าต่าง ก ลองตัวกรอง **แก้ไขแท็บได้ → แก้ไข งบและค่าใช้จ่าย ได้** สมชายต้องอยู่ในผลลัพธ์ เปลี่ยนเป็นแท็บที่สมชายไม่มี E แล้วสมชายต้องหายจากผลลัพธ์ ล้างตัวกรองก่อนขั้นต่อไป

## 4. แม่แบบ กล่องสิทธิ์ การแยกผู้แก้ไข/ผู้อนุมัติ และ special — 5 นาที

ในหน้าต่าง ก เปิด **จัดการ** ของสมชาย:

1. ตอนยังไม่เปลี่ยนอะไร **บันทึก** ต้องกดไม่ได้ เลือกแม่แบบ Manager อย่างเดียว กล่องยังไม่เปลี่ยน; กด **ใช้แม่แบบนี้** จึงคัดลอกกล่องลงร่างใน panel ตรวจ diff ซึ่งบอกชื่อและรุ่นแม่แบบ ก่อนกดบันทึกบัญชีในหน้าต่าง ข ยังมีสิทธิ์เดิม
2. ที่ Projects/Brands/Promotions เมื่อเลือก E ต้องเลือก A พร้อมกันไม่ได้ มีเหตุผลอธิบาย; เอา E ออกก่อนจึงเลือก A ได้ Releases ไม่มีช่อง E ให้เลือก ส่วน Actuals/Questions มี V อย่างเดียว Finance อนุญาต E และ A พร้อมกัน
3. ตรวจสามแถวพิเศษ **จัดการรายการแบรนด์**, **ตรวจเลขที่บันทึกและรายการแก้ไข**, **ระงับการลบเอกสาร**: เมื่อไม่มี V ของแท็บนั้น special ต้องกดไม่ได้ เมื่อมี V จึงเลือกได้ การติ๊ก A อย่างเดียวไม่ได้แทน special
4. เลือกแม่แบบ **ผู้ดูแลระบบ** และกดใช้แม่แบบ ดูสิทธิ์ข้อมูลกว้างขึ้น แต่ช่อง **จัดการผู้ใช้และสิทธิ์** ต้องไม่เปิดเอง อย่าเปิดหรือบันทึกในขั้นนี้ กด Esc ปิด panel แล้วเปิดใหม่ กล่องต้องเป็นค่าเดิมของสมชาย
5. เลือก Manager → ใช้แม่แบบ → อ่าน diff → บันทึกหนึ่งครั้ง ต้องมีข้อความสำเร็จเห็นชัด และประวัติการปรับสิทธิ์บอกความต่าง กลับหน้าต่าง ข แล้วโฟกัส/รีเฟรช ต้องได้สิทธิ์ Manager โดยไม่มีสิทธิ์แก้ไขร่างโครงการ จากนั้นคืนสมชายตามขั้นตอนคืนค่าด้านล่างทันที

**วิธีคืนสมชาย:** ใช้แม่แบบ **ผู้แก้ไขข้อมูล รุ่น 1** แล้วปรับร่างให้เหลือ Projects V+E, Brands V, Promotions V, Finance V+E; เอา Releases/Knowledge/Questions และแท็บอื่นออกทั้งหมด รวมทั้ง specials ทุกช่อง; **จัดการผู้ใช้และสิทธิ์ = ไม่เลือก** อ่าน diff แล้วบันทึก หลังคืนต้องแสดงว่าเป็นค่าที่กำหนดเองจาก editor

การแยก E/A นี้ยังไม่ใช่กฎห้ามอนุมัติฉบับที่ตนเคยแก้ไขทุกครั้ง กฎตรวจผู้เขียน revision แบบ four-eyes เป็นงานที่เลื่อนไว้ตาม owner decision

## 5. สิทธิ์จัดการผู้ใช้แยกจากข้อมูล, no-self และ last manager — 3 นาที

หน้าต่าง ก เปิดสมชาย ติ๊ก **จัดการผู้ใช้และสิทธิ์** ต้องเห็นช่องยืนยันเพิ่ม และบันทึกไม่ได้จนยืนยันว่าเข้าใจสิทธิ์นี้ อ่าน diff แล้วบันทึก โดยไม่เพิ่มกล่องข้อมูลอื่น หน้าต่าง ข ต้องเข้าผู้ใช้และสิทธิ์ได้ ขณะที่แท็บที่ซ่อนไว้ยังซ่อนอยู่

ในหน้าต่าง ข เปิดจัดการบัญชีตนเอง ต้องเห็น **นี่คือบัญชีของคุณ** และแก้กล่อง/ตัดสินบัญชีตนเองไม่ได้ จากนั้นหน้าต่าง ก เอาสิทธิ์จัดการผู้ใช้ของสมชายออก เมื่อหน้าต่าง ข กลับมาโฟกัสหรือส่งคำขอใหม่ ต้องอ่านรายการบัญชีต่อไม่ได้ ข้อมูลรายชื่อที่เคยแสดงต้องถูกเอาออก หากมีบันทึกผู้ดูแลที่พิมพ์เองค้างอยู่ ต้องมีทางกู้ข้อความที่พิมพ์เอง โดยไม่เก็บรายชื่อหรือข้อมูลผู้ใช้อื่นไว้

เปิด panel ของ **ผู้ดูแลสำรอง (UAT)** ในหน้าต่าง ก ตรวจ no-self อีกครั้ง **ไม่ต้องลดสิทธิ์หรือระงับผู้ดูแลเดิมเพื่อทำให้เหลือคนเดียว** กรณี last manager ตรวจจากภาพ `manage-last-manager.png` และ SQL/API/UI บนฐานทดสอบทิ้ง: บัญชีที่เป็นผู้จัดการคนสุดท้ายมีช่องเอาสิทธิ์จัดการผู้ใช้ออกและปุ่มระงับที่กดไม่ได้ พร้อมข้อความ **ต้องเหลือผู้ดูแลระบบอย่างน้อย 1 คน** ฐานข้อมูลตรวจซ้ำแม้ข้าม UI

## 6. ใช้แม่แบบกับหลายบัญชีและยืนยันรายคน — 4 นาที

หน้าต่าง ก เปิด **ปรับสิทธิ์หลายบัญชี**:

1. **เลือกกลุ่มด้วย** มีรายคน / แม่แบบเดิม / ทีม ลองดู preview ของแต่ละแบบแล้วปิดได้ แต่การกดใช้จริงใน UAT ให้เลือกเฉพาะ **สมชาย ทดสอบ** เท่านั้น
2. เลือก **คัดลอกแม่แบบทั้งหมด → ผู้อ่านข้อมูล** แล้ว **ดูความแตกต่างก่อนยืนยัน** ต้องเห็นชื่อเป้าหมายและ diff ของสมชายเพียงคนเดียว หัวข้อ **ใช้กับ 1 คน** และปุ่มใช้จริงต้องรอยืนยันความแตกต่างก่อน
3. ลองเปลี่ยนเป้าหมายหรือแม่แบบหลัง preview ต้องสร้าง preview ใหม่ ไม่ใช้ผลเก่าบันทึกได้ ลอง preview โดยเลือกตนเอง/บัญชีระงับ/เอเจนซีร่วมด้วย ต้องแสดงเป็นบัญชีที่ไม่เปลี่ยนพร้อมเหตุผล จากนั้นกลับมาเลือกสมชายคนเดียวและ preview ใหม่
4. ยืนยันและกด **ใช้กับ 1 คน** ตรวจผลสำเร็จและประวัติ สิทธิ์จัดการผู้ใช้ต้องไม่เปลี่ยนจากงานแบบกลุ่ม คืนสมชายให้เป็นสี่แท็บเดิมตามขั้น 4

การเพิ่มแม่แบบรุ่นใหม่ไม่เปลี่ยนบัญชีเก่าที่ตรึงรุ่นไว้เอง ตัวเลือกแม่แบบและ diff ต้องระบุรุ่น การทดสอบสร้างรุ่นใหม่และตรวจว่าไม่แพร่สิทธิ์อัตโนมัติอยู่ในชุดฐานข้อมูลทิ้ง ไม่ต้องแก้ catalog ผ่าน SQL ในรอบเจ้าของงาน

## 7. แท็บที่ไม่มี V: เมนู, URL, API, ผู้ช่วย และ CSV — 6 นาที

หน้าต่าง ก เอา **Brands V** ออกจากสมชายเพียงช่องเดียวแล้วบันทึก หน้าต่าง ข กลับมาโฟกัสหรือรีเฟรช เมนูแบรนด์ต้องหาย แต่ Projects และ Finance ต้องยังใช้ได้ หน้าจอโครงการแสดงชื่อแบรนด์อ้างอิงที่จำเป็นได้ ไม่ควรเปิดรายละเอียด/ค้นหาเนื้อหาแบรนด์ที่ถูกซ่อน

ใช้หน้าต่าง ข เปิด URL ต่อไปนี้ใน origin local เดิม ตรวจ HTTP ใน DevTools → Network โดยไม่คัดลอกค่า Authorization/Cookie:

| URL แบบอ่านอย่างเดียว | ผลสำหรับสมชายในขั้นนี้ |
|---|---|
| `/?view=brands` | หน้าไม่อนุญาต, HTTP 403 |
| `/api/hub/v1/admin/brands` | 403 ไม่มีรายการแบรนด์ |
| `/api/hub/v1/admin/brands/completeness.csv?status=all` | 403 ไม่มีไฟล์ CSV/ข้อมูลแบรนด์ให้ดาวน์โหลด |
| `/ads/archive` และ `/api/hub/v1/admin/ads/archive` | 403 ไม่มีข้อมูลคลังเอกสาร |
| `/ads/registry` และ `/api/hub/v1/admin/ads/registrations` | 403 ไม่มีทะเบียนแคมเปญ |
| `/api/hub/v1/admin/ads/memos` | 200 เฉพาะข้อมูล Finance ที่มีสิทธิ์ |
| `/api/hub/v1/admin/ads/finance-references` | 200 เฉพาะชื่อ/รหัสอ้างอิงที่ Finance ต้องใช้ ไม่ได้ให้สิทธิ์อ่านรายละเอียด Registry |

กลับหน้า Projects เปิดผู้ช่วย **จำลองในเครื่อง** ลองถามหาแบรนด์/เอกสารคลังที่ซ่อนไว้ ต้องไม่มีคำตอบ ข้อความอ้างอิง citation หรือลิงก์แหล่งข้อมูลที่เปิดเผย payload ภายในของแท็บนั้น การปฏิเสธ/คำอธิบายว่าไม่มีสิทธิ์เป็นผลที่ถูกต้อง ไม่ใส่ข้อมูลผู้ใช้หรือคำขอสมัครเป็นคำถาม หลังทดสอบคืน **Brands V**

ข้อมูล consumer ที่เผยแพร่แล้วและเป็น payload เดียวกับเว็บไซต์สาธารณะยังอ่านได้สำหรับบัญชีภายใน ACTIVE แม้ไม่มีกล่องแท็บ นี่เป็นข้อยกเว้นที่เจ้าของอนุมัติ ไม่ครอบคลุมร่าง ข้อมูลภายใน หรือไฟล์ส่วนตัว ภาพ/ไฟล์ส่วนตัวต้องอ่านผ่าน binding ที่ผู้ใช้มีสิทธิ์; ไฟล์ใหม่ที่ตนอัปโหลดและยังไม่เคย bind ใช้ได้เฉพาะ workflow อัปโหลดที่มีสิทธิ์ การทดสอบ bytes/thumbnail/dispatcher และ direct SQL อยู่ในชุดอัตโนมัติ ไม่ต้องนำไฟล์จริงเข้า UAT

## 8. ข้อความแท็บใหม่และ rollout แบบเจาะจง — 3 นาที

ในผู้ใช้และสิทธิ์ของหน้าต่าง ก ต้องมี **มี Tab ใหม่: ผลใช้จ่ายรายเดือน** สำหรับผู้ดูแลสำรองที่ยังไม่รับทราบ นี่คือ **การซ้อม rollout ด้วย Actuals ซึ่งเป็นแท็บเดิมที่มี DB guard แล้ว** ไม่ใช่แท็บปลอม และไม่ได้ให้สิทธิ์เพิ่มแก่บัญชีเดิมจากการ seed

กด **กำหนดสิทธิ์แท็บนี้** เลือกเฉพาะสมชาย เลือก V แล้วดู preview: diff ต้องเพิ่มเฉพาะ Actuals V ไม่มีแท็บอื่นหรือสิทธิ์จัดการผู้ใช้เปลี่ยน ยืนยันใช้กับ 1 คน หน้าต่าง ข ต้องเห็นผลใช้จ่ายรายเดือนและอ่านได้ จากนั้นหน้าต่าง ก เอา Actuals V ของสมชายออกให้เหมือนเริ่มต้น

กด **รับทราบโดยไม่ให้สิทธิ์** ข้อความหายสำหรับผู้ดูแลคนนี้ แต่สมชายยังไม่มี Actuals V การรับทราบของผู้ดูแลคนหนึ่งไม่ใช่การรับทราบแทนทุกคน หากเคยซ้อม/รับทราบแล้วข้อความไม่กลับเอง ให้ใช้หลักฐานภาพและผลอัตโนมัติ ไม่แก้ฐานเพื่อรีเซ็ต การเพิ่ม catalog tab ใหม่จริงแล้วไม่มีใครได้สิทธิ์อัตโนมัติทดสอบแยกในฐานทดสอบทิ้ง

## 9. ระงับมีผลคำขอถัดไปและคืนสถานะ — 3 นาที

เปิด Projects ของสมชายค้างในหน้าต่าง ข หน้าต่าง ก ระงับ **สมชาย ทดสอบ** พร้อมเหตุผลสังเคราะห์ `ทดสอบ UAT — จะเปิดใช้งานอีกครั้งทันที` ต้องกรอกเหตุผลก่อนยืนยัน ให้หน้าต่าง ข ส่งคำขออ่านใหม่/กลับโฟกัส/รีเฟรช: API งานต้องปฏิเสธ และพาไปหน้าสถานะที่เห็นเหตุผล ไม่ค้างใช้ข้อมูลสิทธิ์เดิมต่อได้ `/v1/me` ยังอ่านสถานะ SUSPENDED ได้

หน้าต่าง ก กด **เปิดใช้งานอีกครั้ง** ของสมชาย ต้องกลับ ACTIVE กล่องสี่แท็บเดิมยังอยู่ เหตุผลระงับไม่แสดงเป็นเหตุผลปัจจุบันแล้ว แต่ประวัติผู้ดูแลยังตรวจย้อนหลังได้

เลือก **บัญชีระงับ (UAT)** อีกครั้งเพื่อตรวจหน้าสถานะและตัวเลือกบัญชี local จากนั้นสลับกลับสมชาย บัญชีระงับต้นแบบนี้ให้คง SUSPENDED ไม่ต้องเปิดใช้งาน การอัปเดตหน้าคำขอ/สถานะระหว่างรออนุมัติใช้การอ่าน `/v1/me` ทุก 30 วินาทีขณะเอกสารมองเห็นและเมื่อโฟกัสกลับ; สถานะต้องเปลี่ยนในหน้าเดิม โดยไม่ทิ้งข้อความร่างที่แก้ค้างเงียบ ๆ

## 10. เอเจนซีและขอบเขตของตน — 3 นาที

เลือก **เอเจนซี KIN** แล้ว **เอเจนซี COMBAY** ทีละบัญชี ต้องเห็นเฉพาะทะเบียนที่อนุญาต ไม่มี Projects/Finance/Archive/Accounts/ผู้ช่วย และเข้า `/ads/registry/new` ไม่ได้ บัญชีภายนอกไม่สามารถออกทะเบียนเองหรือทำ stewardship ของ operator

ภายใต้ KIN เปิด `/api/hub/v1/admin/ads/registrations?agency=COMBAY` ต้องได้รายการว่าง ไม่ได้ข้อมูล COMBAY; filter ของ KIN ต้องเห็นเฉพาะ KIN หากมีรายการสังเคราะห์ของอีกเอเจนซีที่ทราบรหัส การเปิดรายละเอียดข้ามเอเจนซีต้องถูกปฏิเสธ/ไม่พบข้อมูล ทำซ้ำกลับด้านกับ COMBAY

ในหน้าต่าง ก เปิดจัดการบัญชีเอเจนซี กล่องเป็นโปรไฟล์ตายตัวพร้อมคำอธิบาย ไม่ปรับเป็นบัญชีภายในหรือให้กล่องเพิ่มเอง รหัสเอเจนซีต้องมาจาก canonical code ที่ใช้งานอยู่ หากฐานทำงานไม่มีทะเบียนสังเคราะห์ให้ทดสอบการ bind **อย่าออกชื่อหรือเปิดสวิตช์อนุมัติ global เพียงเพื่อสร้าง fixture** บันทึกว่าไม่มี fixture สำหรับการตรวจแบบบวกด้วยมือ แล้วใช้ผล SQL/API/UI บนฐานทดสอบทิ้งที่มี KIN/COMBAY ทั้งสองฝั่งเป็นหลักฐานของ own-binding และ cross-agency denial

## 11. คืนค่าปิดรอบและบันทึกผล — 2 นาที

ตรวจในหน้าต่าง ก ก่อนจบ:

- **สมชาย ทดสอบ** = ACTIVE, กำหนดเองจาก editor รุ่น 1, Projects VE / Brands V / Promotions V / Finance VE เท่านั้น, ไม่มี special, ไม่มี Actuals, ไม่มีสิทธิ์จัดการผู้ใช้
- **ผู้ดูแลสำรอง (UAT)** = ACTIVE และมีสิทธิ์จัดการผู้ใช้; **บัญชีระงับ (UAT)** ยังคง SUSPENDED
- บัญชีเดิมทั้งแปดและ BNA7 ไม่ถูกแก้ระหว่าง UAT ไม่มีการแก้ข้อมูลธุรกิจหรือระบบต้นทาง
- ตรวจว่าไม่ต้องการบันทึกร่างทดสอบแล้วจึงปิด panel ไม่จำเป็นต้องลบประวัติ UAT; ประวัติต้องอยู่เพื่อตรวจสอบ

seed เป็นแบบเพิ่มเมื่อยังไม่มีและรักษาสิ่งที่มีอยู่ **รัน seed ซ้ำไม่คืนค่าที่เปลี่ยนระหว่าง UAT** จึงต้องคืนผ่านหน้าจอตามรายการข้างต้น การรับทราบ notice เป็นการเปลี่ยนที่ตั้งใจให้คงอยู่ได้

บันทึกผลเป็น `ขั้น / ผ่านหรือไม่ / สิ่งที่เห็น / เวลา / ภาพจากบัญชีสังเคราะห์` หากติดขัด ระบุ URL และ HTTP status ได้ แต่ไม่แนบ secret หรือ payload ของโครงการจริง งานนี้ยังไม่เปิด hosted และไม่ต้องใช้ข้อความ “credentials ready” ในรอบ local นี้
